What is verified, and how

  • Product facts come from each product’s own listing, read on 2026-11-19, with the URL recorded per field in the verification register. Where a listing contradicts itself, both values are published and flagged rather than silently resolved (FLG-002, FLG-021, FLG-022).
  • Policy text was read from the official pages and quoted, not summarised from memory: Operating Agreement §5 (disclosure), Program Policies (price and availability, ratings), Google Search Central (outbound link qualification), FTC (disclosure placement). Sources are listed on the compliance page with the read date.
  • Mechanical checks run before every publish: the build is deterministic, and four gates check disclosure placement, sponsored marking, internal links, metadata, voice rules, price policy, and now that every CSS class actually has a style. A page that fails cannot merge.

How money and measurement work

Outbound links carry tracking ID shopnow047c-20 and are marked rel="sponsored" with a visible label, including the links the chooser script builds. Five privacy-preserving events are defined; they are counted in the visitor’s browser only, because no endpoint is hosted. The campaign ledger starts empty and only accepts figures from authorised first-party reports, with a date. No conversion score or revenue forecast appears anywhere on this site.

What this pass changed

  • The site now looks designed, because the styles exist. The build was emitting 44 CSS classes with no rule and referencing 9 undefined custom properties, so cards, hero columns and status chips rendered as plain blocks. All of it is styled, and scripts/check_style.mjs fails the build if an unstyled class returns (FLG-052).
  • Broken markup repaired. Three suggestion rows had malformed class attributes, so their status badges and row text never rendered (FLG-053).
  • The social card is readable. The shared-link image had text overlapping the subtitle and captions hidden under the footer; make_og.py now measures each block and asserts clearance (FLG-054).
  • Readers can ask for a topic. The desk now has an intake that opens a public issue, and shows an honest count of zero rather than pretending to have submissions (FLG-055).
  • Search metadata fits. Five titles and descriptions that would truncate in results were rewritten; the metadata gate now reports zero warnings.

What happens next, in order

  1. You run the Special Link test once per product in Associates Central and confirm the destination and the tracking report. This is the one gate no session can clear from inside the repository (SG-01).
  2. Claim the Search Console property for the canonical host and submit the sitemap. Without it the calendar is a plan, not a measurement (SG-02).
  3. Pick the domain and the build source — a custom domain if you want one, and GitHub Pages set to publish from Actions so a failed gate actually blocks a release (SG-43).
  4. Write the next guide from measured queries, four weeks after step 2, not from instinct.

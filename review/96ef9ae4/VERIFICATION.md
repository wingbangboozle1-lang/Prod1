## Irregularities / notes (non-blocking)

- **Before this pass the live site served GitHub's stock 404 page** for missing paths — no
  disclosure, no navigation. That is the gap this record closes; it was never a data error,
  so no `flagged.html` row is required (the fix is in this same PR).
- **`fetch_page` cannot observe a 404 response body** (it fails the request rather than
  returning the error page), so the before/after proof for source 1 is the GitHub Docs rule
  plus the presence of `404.html` at the publishing-source root — recorded here rather than
  claimed as a live fetch.
- Google's "server returns a 404 HTTP status code" requirement (source 2) is GitHub Pages
  platform behaviour for missing paths and cannot be altered from the repo; a direct visit
  to `/404.html` answers 200, which is why the `noindex, follow` meta (row 5) is load-bearing.

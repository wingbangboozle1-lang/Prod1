# Prod1 — The Countertop Guide (Amazon Affiliate Publication)

Spec-backed affiliate publication for air fryers & meat thermometers. Static GitHub
Pages site. No build step to deploy: edit `data/products.json`, run
`python3 build_site.py`, commit — the Pages workflow publishes after the gate passes.

## Live site
GitHub Pages from `main` (see `.github/workflows/pages.yml`, which runs `node scripts/check_site.mjs` before deploy). Canonical is the per-page GitHub Pages URL (`https://wingbangboozle1-lang.github.io/Prod1/<page>`) — a custom domain remains an owner decision (see `flagged.html` FLG-007 and `suggestions.html` SG-02).

- `executive-summary.html`, `verification.html`, `flagged.html`, `compliance.html`,
  `methodology.html`, `search.html` — dashboard surfaces (footer + "The desk" nav group)
- `data/products.json` — single source of truth (verified 2026-11-19; re-verified same day)
- `assets/style.css`, `assets/app.js` — publication design + chooser/search/analytics (local-only)
- `sitemap.xml`, `robots.txt`, `feed.xml` — generated by `build_site.py` (deterministic dates)

## Rules (do not break)
1. Disclosure above the fold on every page + footer, using the exact Operating Agreement
   §5 sentence: "As an Amazon Associate I earn from qualifying purchases." Every outbound
   product link `rel="sponsored"` + labeled.
2. Every product fact links to its Amazon listing. Missing = blank + flagged. Never infer.
   Intended ASIN and observed redirect target stay in separate fields.
3. No hands-on testing / trending / revenue claims without evidence. Seller claims
   attributed ("per listing"). Prices always carry a snapshot date.
4. Where a listing contradicts itself, publish both values and flag the conflict
   (never silently resolve: FLG-002, FLG-021, FLG-022).
